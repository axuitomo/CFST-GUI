# CFST-GUI v2.1.7

## 变更摘要

本版修复设置页在标准模式下「追踪 URL 看起来丢失」：两个 COLO 获取模式现在都保留并保存追踪 URL，切到「追踪URL」时不再拿到空端点；同时把追踪有效状态码固定为 `200`，界面上不再可改，旧配置里的 `0`（不限制）、`204` 一读入就归一化为 `200`。

### 修复

- 修复切换 COLO 获取模式后追踪 URL 为空：切到「追踪URL」而地址为空时，自动填入从文件测速URL派生的 `/cdn-cgi/trace`，与标准模式实际使用的端点一致；已有地址在两种模式之间切换、保存与重启后都原样保留。
- 标准模式不再把追踪 URL 降级成灰显的「备用端点」：字段在两种模式下都可编辑、都写配置，提示文案改为说明标准模式用它决定追踪请求的 Host/SNI 并作为备用端点，`trace_colo_mode=trace_url` 时只请求该地址本身。
- 新增用例 `TestSanitizeConfigSnapshotKeepsTraceURLInStandardMode`，锁定标准模式下 `trace_url` 与 `trace_colo_mode` 经配置快照读写与 `ProbeConfig` 转换后不被派生地址顶掉。

### 变更

- 追踪有效状态码固定 `200`：设置页只显示不可修改的「200（固定）」，删除输入框与 `200`/`204`/「不限制」选项，摘要行同步显示该值。
- 后端归一化与配置快照读写把非 `200` 的 `trace_status_code` 一律改写为 `200`（旧配置的 `0`、`204` 读入即变 `200`），归一化时给出 warning；追踪阶段只接受正常响应，拦截页与限流页不再可能被当成有效追踪。
- 锁死 `200` 的连带效果：`canFallbackToTCPCandidates`（只在状态码为 `0` 时触发的整批 TCP 回退）不再生效；追踪阶段的临时异常软通过逻辑不变。
