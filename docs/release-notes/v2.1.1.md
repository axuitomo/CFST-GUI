# CFST-GUI v2.1.1

## 变更摘要

### 探测吞吐

- 阶段 1 的 TCP 采样改为并发发出（`internal/task/tcping.go`）：一次 TCP 建连只花 1×RTT（死 IP 只花 1×超时），此前串行跑 `ping_times` 次会把一颗 IP 的墙钟成本放大成 N 倍，而阶段 1 要过完整个候选池。一次真实跑法里 13863 颗候选有 11948 颗全超时，光这一阶段就花了 122 秒；并发后同一跑法的阶段 1 预期压到 30~45 秒。丢包率与平均延迟仍按 `ping_times` 个独立样本统计，口径不变；代价是同时在飞连接数从 `routines` 变成 `routines × ping_times`，暂停与终止只在一批采样的边界生效（最多等一个超时）。
- 追踪阶段并发上限从 30 提升到 100（`MaxHeadRoutines` / `MaxTraceRoutines`）。同一跑法里 1915 颗候选在 30 并发下被 2 秒超时拖成 100 秒，抬到 100 后预期约 30 秒；每颗 IP 打的是不同边缘节点，429 仍按既有退避处理。已在配置里显式写过阶段 2 并发的用户保持自己的值。
- 连续失败冷却不再把「候选本身不通」算进去（`internal/task/retry.go`）：只有耗时不到该阶段超时预算 1/10 的失败（路由不可达、端口耗尽这类链路异常）与 worker 崩溃才计入冷却，文件测速阶段的失败全部按候选侧处理。此前每颗超时的死 IP 都推进一次计数，实测一次 13863 颗候选的跑法触发了 1051 次 2500ms 冷却，而每次只让一个 worker 停一下、另外 199 个照常探测，等于纯损失约 11% 的阶段 1 墙钟时间。`cooldown_policy` 的字段与默认值不变，0 仍然等于关闭。
- 文件测速的「最低下载速度」现在同时是提前收工线：预热结束再留两个采样窗口后，累计峰值仍低于下限的 IP 会立刻结束测量，不再跑满整个测量窗口。这类 IP 本来就会被下限淘汰，结果不受影响；下限为 0（默认）时行为不变。

### 前端冷启动

- `vue` 升级到 `3.6.0-rc.15` 并改用裸 `vue` 的默认入口（`vue.runtime.esm-bundler`）。该版本起默认入口同时再导出 `@vue/runtime-vapor`，Vapor SFC 不必再别名到预构建的 `runtime-with-vapor` 包，打包器可以按实际引用裁剪：首屏 `app.js` 从 502 KB 降到 486 KB（gzip 159 → 153 KB）。8× CPU 节流下挂载时间从 939~988ms 降到 779~787ms。附带收益是 dev / build / Vitest 统一到同一个 `vue` 入口。
- 启动画面的淡出从 `0.18s / 240ms` 压到 `0.12s / 160ms`：骨架屏移除后骨架屏节点存活时间从 244ms 降到 160ms 左右（真实桌面进程实测挂载后 93ms 完成移除）。
- 启动同步链改为等首帧画完再跑（`waitForFirstPaint()`，双 rAF + 250ms 上限）：探测与拖放监听器仍然先注册，之后让出一帧让浏览器把用缓存回填的看板画出来，再去读配置与任务快照。慢机上用户更早看到可用的界面，而不是在骨架屏后面等 IPC 链。

### Android

- 修复设置页点开输入框时页面像卡死：软键盘以 `adjustResize` 压缩窗口后，固定标题栏与底部导航占满整条视口，横屏下（914×411 只剩约 124 CSS px）内容区整片空白、竖屏下聚焦的字段被标题栏盖住。键盘态此前用 `innerHeight - visualViewport.height` 判定，而这两个高度随窗口同步缩小、差值恒为 0，标志位永远停在「关闭」；现在改为与「无键盘时的视口高度」基线比较（基线只在焦点不在文本控件时刷新，`frontend/src/lib/androidViewport.ts`），键盘打开时收起标题栏与底部导航，并把 `.mobile-main` 为标题栏预留的 `padding-top` 归零。

### 修复

- 阿里云 DNS 签名的 query map 不再按外部入参长度预分配（`internal/alidnscore/alidns.go`）：`params` 来自外部配置，长度加法在极端输入下会溢出得到负的分配尺寸；这个 map 只有十来个键，容量提示没有意义。
