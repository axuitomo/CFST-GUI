# CFST-GUI v2.0.4

## 撤回背景

[v2.0.3](./v2.0.3.md) 发布后确认了文件测速实时速率的读数缺陷：单次采样间隔内的字节数会被系统缓冲和连接重连打散，用它做除数就会得到 0 与尖峰交替的读数，收尾采样还会显示为 `-`。该问题只影响界面读数，不影响最终结果与 CSV，但对“正在测什么速度”的判断是硬伤，因此把 2.0.3 的 GitHub Release 转为 draft 撤回，代码、`v2.0.3` 标签与原有发行资产保留在仓库中，修复随 2.0.4 重新发布。撤回期间公开 latest 保持 `v2.0.2`。

## 变更摘要

### 修复

- 实时速率改为按最近 1 秒滑动窗口计算，刷新节奏与窗口对齐（`download_speed_sample_interval_ms` 默认改为 `1000`，更小的值按 1 秒执行），读数不再在 0 与尖峰之间跳动，收尾采样不再显示 `-`；最高速率同样取窗口速率且不低于平均速率。这就是 2.0.3 撤回的原因。
- 403 / 1034 的 IP 只要没测到速率就一律丢弃：不进结果、不写 CSV、不占 `download_success_limit` 配额，开关只决定是否重试和是否计入连续失败冷却。
- 设置页第一次展开或收起卡片不再整页抖动：展开动效只作用于切换普通/高级时新出现的分区，卡片本身用常开的 `::details-content` 高度过渡。
- 所有 403 / 1034 淘汰都不再靠调试日志才能看见：新增 `probe.edge_rejected` 事件，进程面板直接显示「边缘 IP 受限 1034」或「HTTP 403 拒绝」，不需要打开 debug。

### 新增

- 「网络与任务 → DNS 与 ECH」独立设置卡片，集中放 DoH 地址（含阿里 / DoH.pub / Cloudflare 预设与自定义）、ECH 开关、ECH 域名和 ECH 配置。
- 新增 `doh.test` 命令与「测试 DoH」按钮：用当前配置的端点解析测试主机并报告 IPv4/IPv6 数量，再按手填配置、来源主机 HTTPS RR、ECH 域名的顺序报告 ECHConfigList 来源与字节数。测试路径不回退系统 DNS；合法 NXDOMAIN 视为端点可用；非法 ECH 域名或 base64 配置降级为自动获取并给出警告。
- 403 与 1034 拆成两个独立开关：`probe.ignore_403` / `-ignore-403`（默认开启）与 `probe.ignore_1034` / `-ignore-1034`。屏蔽即跳过（不重试、不计冷却）；不屏蔽则按普通失败处理（按 `retry_policy` 重试并计入冷却）。1034 判定优先于 403。
- `probe.custom_host_sni` 总开关（默认关闭）：关闭时 `host_header`、`sni`、`download_host_header`、`download_sni` 一律不生效，Host 与 SNI 跟随 URL（追踪阶段跟随 `trace_url`）。旧配置没有该字段时，只要填过任一字段就按开启处理，升级前后请求身份不变；CLI `-host` / `-sni` 传入即自动开启。
- 文件测速 URL 从「探测策略 → 第三阶段」的高级专属区域提到「探测策略」顶部，普通设置里也能直接改；追踪 URL 留空时仍由该地址派生 `/cdn-cgi/trace`。

### 变更

- `probe.ignore_1034` 默认值从 `true` 改为 `false`：边缘 IP 受限不再默认跳过，而是按普通失败处理（重试并计入冷却）。旧配置里显式写入的值继续保留；需要旧行为请在设置页勾选「屏蔽 1034」或传 `-ignore-1034`。
- 结果 CSV 统一为 10 列：`IP 地址、已发送、已接收、丢包率、TCP延迟(ms)、平均速率(MB/s)、最高速率(MB/s)、地区码、追踪延迟(ms)、备注`。任务自写的 `result.csv` 与结果页「导出 CSV」从此是同一个形状（此前前者 8 列、后者 9 列且末列不同）。旧文件仍按表头读取；追加模式下新写入的行会比旧表头多列。
- 阶段 1 HTTPing 的 403 淘汰改用 `reason=forbidden`（此前与其它状态码不匹配共用 `status_mismatch`），两类边缘拒绝在 `stage.reject`、`probe.edge_rejected` 和文档里统一用同一套名词；非 403 的状态码不匹配仍是 `status_mismatch`。

## 发布渠道

- `2.0.4` 为纯数字版本，会作为正式 Release 接管 latest；应用内更新检查读取 GitHub Releases latest。
- Android `versionCode` 从 `20003` 提升到 `20004`，`scripts/build/version-bump.sh 2.0.4 --android-code 20004 --apply` 已同步默认版本号，可直接覆盖安装 v2.0.2（覆盖 2.0.3 也可）。
- 2.0.3 的 draft Release 维持 draft，不重新发布；需要历史版本的用户请安装 2.0.4。
