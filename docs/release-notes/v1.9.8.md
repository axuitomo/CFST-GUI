# CFST-GUI v1.9.8

## 变更摘要

- Windows 发行形态改为 NSIS 安装器：默认资产 `cfst-gui-windows-amd64.exe` 是安装器，同时保留免安装便携版
  `cfst-gui-windows-amd64-portable.exe`；两者都做代码签名，安装器内置的应用二进制与安装器自身分别签名。
- 打通原本失效的 NSIS 编译链路：本地 `scripts/build/build-release.sh` 先由 `wails3 generate build-assets`
  生成 `wails_tools.nsh`，再用 `makensis` 打包，CI 发布工作流与本地使用同一条流程并预装 NSIS。
- 修复 `build/windows/installer/project.nsi` 的三个编译阻塞点：补回 UTF-8 BOM（否则 `Unicode true` 读中文串报
  `Bad text encoding`）、`OutFile` 指向 `build/artifacts/release/desktop/`、`CreateShortCut` 改用字面显示模式；
  同时移除无法实现的“显示命令行窗口”可选组件，桌面快捷方式保持默认显示模式。
- 安全加固（对应本地安全审计的 C1/C2）：WebUI 默认只绑定 `127.0.0.1:34115`；绑定非回环地址必须提供
  `CFST_WEBUI_TOKEN`，否则拒绝启动；Docker/Compose 模板不再提供公开默认令牌 `change-me`，令牌为空时
  `docker compose` 直接报错；`/api/command/runtime.status` 默认仅本机可用，远程访问需要显式开启。
- 更新包解压增加纵深防御上限：zip 与 tar.gz 单文件 512 MiB、解压总量 1 GiB，超限立即失败并附带包内路径。
- 前端：修正 Wails 运行时探测。`@wailsio/runtime` 模块在任何 DOM 环境都会创建空对象 `window._wails`，
  旧判断 `"_wails" in window` 在 WebUI/浏览器里恒为真，WebUI 因此误走桌面 IPC 通道，命令被发往不存在的
  `/wails/runtime`：返回 405、失败且无任何提示；现在只认可 Wails 桌面宿主注入的 `_wails.environment`。
  修复后 WebUI 恢复 `/api/command/*` HTTP 通道、桌面窗口控制按钮在 WebUI 下不再渲染、每次页面加载的
  `/wails/runtime` 405 一并消失；`@wailsio/runtime` 主窗口改为惰性获取，设置页补暗色模式配色。
  WebUI 请求日志只记录方法/路径/状态，不再打印请求体（调用参数含令牌等敏感配置）。
- Android 修复：`SchedulerWorker` 不再调用 `setForegroundAsync()`，避免 Android 14+ 冷启动时 WorkManager
  因缺少 foregroundServiceType 抛 `InvalidForegroundServiceTypeException`，定时任务改由自带
  `ProbeForegroundService` 承接前台通知；`android:allowBackup` 改为 `false`。
- 工具链基线统一升级：JDK 25、AGP 9.3.2、NDK r30、Wails `v3.0.0-beta.20`、pnpm 12.3.4、vite 8.3.0、
  `@wailsio/runtime` 3.0.0-beta.20，工作流、构建脚本、校验脚本与文档同步更新。
- Android 静态检查迁移到 detekt 2.0.0-alpha.6：改用 `dev.detekt` 插件与 `detektDebug` +
  `detektDebugUnitTest` 分变体基线，`mobile/android/config/detekt/detekt.yml` 保留 detekt 1.x 的 MagicNumber
  严格口径（属性与局部变量声明不豁免）。

## 已知遗留

以下为本次未处理的安全审计条目，留待后续版本：

- 更新链路的 TLS 校验与完整性哈希仍与下载同信道下发，中间人可替换更新包。
- 配置接口仍以明文回传全部密钥，脱敏只存在于前端显示层。
- 诊断与源文件接口的路径写入/读取仍未收敛到允许目录，目前仅靠默认回环绑定与令牌降低暴露面。
- WebUI 令牌仍接受 URL query 形式且未做限流。
- WebDAV 仍允许 `http://` 明文 Basic 认证。
